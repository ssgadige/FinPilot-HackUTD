00 Design system

#1 / FP-01 · Backend Shared contracts · Agents All roles

Use these tokens and patterns across tasks #1-#8. Financial figures and states are illustrative only.

01 Sign in

#2 / FP-02 · Backend #10 · Agents None

Continue -> verification challenge. No authenticated financial session before email-code verification.

02 Verify your email

#2 / FP-02 · Backend #10 · Agents None

Wrong/expired code -> inline error. Resend cooldown; codes single-use. Local Mailpit receives demo email.

03 Overview

#4 / FP-04 · Backend #12, #13 · Agents #18, #23

Run checkup -> #7 workspace. Each metric opens its source account or calculation. Chat opens from the shared header.

04 Connected institutions

#3 / FP-03 · Backend #11, #12 · Agents Integrity #18

Category -> provider -> simulation login -> consent/account selection -> dashboard. Each connection can be synced or disconnected.

05 Link institution

#3 / FP-03 · Backend #11 · Agents None

Continue validates fictional institution credentials; wrong credentials stay on this screen. No call to the actual bank.

06 Consent & selection

#3 / FP-03 · Backend #11 · Agents Integrity #18

Connect selected -> scoped connection. Unselected accounts are invisible to agents. Disconnect revokes future access.

07 Accounts

#4 / FP-04 · Backend #12 · Agents Integrity #18

Select an account -> filtered transaction history. Manage -> connection flow. Liquid assets stay separate from retirement accounts.

08 Transactions

#4 / FP-04 · Backend #12 · Agents Integrity #18

Filter and paginate on the server; row -> evidence drawer. Paired transfers are labeled, not counted as new income/spending.

09 Cash & bills

#4 / FP-04 · Backend #12, #13 · Agents #18

Date selection highlights responsible accounts and bills. Review adjustment -> plan comparison; no real transfers.

10 Subscriptions

#5 / FP-05 · Backend #13, #14 · Agents #19

Confirm recurrence/usage preferences first. Transaction history alone cannot prove a service is unused. Compare -> offer detail.

11 Offer comparison

#5 / FP-05 · Backend #13, #14 · Agents #19

Choose an option -> save proposed action with confirmation. This does not cancel or purchase anything; fixtures must stay labeled.

12 Debt & readiness

#6 / FP-06 · Backend #13, #14 · Agents #20

Run payoff scenario -> calculation evidence. Purchase readiness is planning, not a score-point prediction or loan approval.

13 Goals & plans

#6 / FP-06 · Backend #14 · Agents #20

Create/edit goal -> target, deadline, priority and buffer. Compare plans -> explicit tradeoffs; acceptance is server-confirmed.

14 Plan comparison

#6 / FP-06 · Backend #14 · Agents #20, #21

Select -> accept dialog with expected plan version. Stale-version conflict -> refresh comparison. No automatic execution.

15 Assets

#6 / FP-06 · Backend #12 · Agents #20

Asset snapshots contribute to net worth; investments and retirement accounts are not spendable cash by default.

16 Agent workspace

#7 / FP-07 · Backend #15 · Agents #17-#24

Run -> poll actual events. Expand findings -> source evidence. Completed/skipped/failed labels come from real run state, never timers.

17 Evidence drawer

#4, #7 / FP-04,07 · Backend #12, #15 · Agents #18, #23

Finding -> evidence references and calculation assumptions. Only records owned by this user and authorized connection are accessible.

18 Scenario lab

#6 / FP-06 · Backend #13, #14 · Agents #21

Preset/input -> deterministic stress results. Baseline stays unchanged. Show first failure date and tested horizon, not a guarantee.

19 Plan repair

#6, #7 / FP-06,07 · Backend #14, #15 · Agents #22, #23

Demo event -> new snapshot -> tool rerun -> proposed revision. Accept explicitly or retain previous accepted plan.

20 Settings

#8 / FP-08 · Backend #10, #11, #12 · Agents None

Logout invalidates session. Disconnect -> explicit confirmation and stale affected findings. Email/security edits are out of scope unless safely implemented.

21 Chat interface

#7 / FP-07 · Backend #15 · Agents #17, #23

Chat can read current scoped findings and request runs. It cannot authorize money movement or fabricate completion; richer chat features come later.

22 State patterns

#1, #8 / FP-01,08 · Backend All endpoints · Agents All roles

Apply these states to each data screen. Preserve context and safe retry behavior; never display a fabricated successful result.

23 Mobile layouts

#1, #4, #7, #8 · Backend Same APIs · Agents Same roles

Mobile stacks cards; navigation opens as a drawer; chat is a separate drawer. Tables retain usable horizontal scroll. Reference screens are not runtime code.

24 Goal editor

#6 / FP-06 · Backend #14 · Agents #20

Save -> validated goal endpoint. Cancel discards unsaved edits. Amount/date errors are inline; changes make dependent proposals stale.

25 Subscription preferences

#5 / FP-05 · Backend #14 · Agents #19

Save preferences -> Deal Scout receives confirmed constraints. Unknown usage remains unknown; a planned change is not realized savings.

26 Accept plan

#6 / FP-06 · Backend #14 · Agents #20, #21

Accept uses expected_version and idempotency key. A stale response shows conflict and refresh; it never silently overwrites a newer version.

27 Disconnect institution

#3, #8 / FP-03,08 · Backend #11 · Agents #18, #22

Disconnect -> revoke access and mark affected findings/plans stale. Cancellation preserves connection; no real bank account is closed.
